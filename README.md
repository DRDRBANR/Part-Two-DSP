# Part-Two-DSP
# Тестовое задание: Разработка цифровой аппаратуры (Часть 2)

## Описание репозитория
Репозиторий содержит материалы второй практической части тестового задания. В структуре проекта представлены решения пяти задач, охватывающих проектирование конечных автоматов, работу с интерфейсами передачи данных, синхронизацию между различными тактовыми доменами и аппаратную оптимизацию логических ресурсов. Директория с первой частью задания, выполненной в среде MATLAB, интегрирована в данный репозиторий исключительно для удобства проверяющих.

## Структура проекта
    
**Задача 1: FIFO RAMB36E2**
Разработка контроллера очереди типа First-in-First-out с использованием аппаратных макросов блочной памяти RAMB36E2. Директория содержит исходный код модуля и тестбенч для верификации корректности записи, чтения и формирования флагов состояния заполненности буфера.

**Задача 2: AXI-Stream MUX**
Проектирование мультиплексора потоковых данных на базе стандарта интерфейса AXI-Stream. Реализована логика арбитража и обработки управляющих сигналов протокола для обеспечения маршрутизации пакетов от нескольких источников к единому приемнику.

**Задача 3: CDC (Clock Domain Crossing)**
Реализация модулей передачи информационных сигналов между асинхронными тактовыми доменами. Проект включает схемы синхронизации, предотвращающие возникновение метастабильности при пересечении границ независимых частотных зон.

**Задача 4: Базовый контроллер светофора**
Разработка модели конечного автомата управления светофором. Модуль реализует логику переключения состояний и обработки асинхронных управляющих сигналов с использованием стандартных программных абстракций.

**Задача 5: Оптимизированный контроллер светофора**
Проведение аппаратной оптимизации модели светофора с целью минимизации потребляемых логических ресурсов ПЛИС. Осуществлен переход к динамически вычисляемой разрядности счетчиков и логике предварительной загрузки констант, что минимизировало количество таблиц истинности и триггеров.

## Порядок запуска и проверки
Каждая задача представляет собой изолированный субпроект. Внутри соответствующих папок размещены поддиректории исходного кода (`src`) и тестбенчей (`tb`). Проверка модулей осуществляется путем запуска самопроверяющихся тестбенчей в симуляторе. Дополнительные материалы расположены в директории `Doc`.
